Some safety stuff first:
According to /ros2_ws/src/hcoil_pkg/hcoil_pkg/include/hcoil_pkg/psu_node.hpp
    int RatedV_ = 50;          // PSU rated voltage
    int RatedI_ = 30;          // PSU rated current
and we are not allowed above 80% of this:
    double vLimit = RatedV_ * 0.8;
    double iLimit = RatedI_ * 0.8;
Meanwhile, in \ros2_ws/src/hcoil_pkg/hcoil_pkg/include/hcoil_pkg/field_node.hpp    
    int maxField_ = 20;
    int maxChange_ = 15;  
maximum absolute field and field change are defined.

Instructions:

1) Turn on coils: wall 3-phase switch, round the back of the coil power supplies, cabinet switch AND button, reverse all this to go home. Make sure RC/LC is illuminated on all 5 supplies.\\

2) cd into /ros2_ws
either: ./start_field.sh
or:
source /opt/ros/humble/setup.bash -> tells PC where ros is installed (this exists above \home)
colcon build --symlink-install  			-> compile
source install/setup.bash  
	-> tells PC where our own ros packages are installed. Don’t change setup.bash!
sudo chmod a+rwx /dev/ttyUSB* 	
	-> permission to write to serial nodes (initial setup)
ros2 launch hcoil_pkg field_launch.py 	
	-> if field_launch.py has worked the red light on the left of the power supply comes on


3) new terminal (1):
cd into /ros2_ws
source /opt/ros/humble/setup.bash 
source install/setup.bash

ros2 run hcoil_pkg publish_field.py 	-> publishes current field
ros2 run hcoil_pkg publish_field.py --ros-args -p bx:=5.0	
	-> sets current field (must be 5.0, not 5)
ros2 topic pub /magfield hcoil_interfaces/msg/MagField "{bx: 0.0, by: 0.0, bz: 0.0}" --once
ros2 run hcoil_pkg publish_field.py --ros-args -p bx:=5.0 -p by:=5.0 -p bz:=0.0


4) new terminal (2):
cd /ros2_ws -> source /opt/ros/humble/setup.bash -> source install/setup.bash

ros2 node list -> /PSU0 … /field
ros2 node info \field -> tells you subsribers and publishers
ros2 topic list
ros2 topic echo /magfield

ros2 topic echo /VI/PSU0 (for example) tells you the V and I to the PSU
PSU0 & PSU1 = B_x
PSU4 = 	 B_y
PSU2 & PSU3=  B_z





ros2 run hcoil_pkg sweep_axis.py 		-> sweeps all fields
ros2 run hcoil_pkg sweep_axis_PRL.py --ros-args -p abs:=12.0 -p axis:=z


CTRL-C to kill all nodes in any given terminal.\\

From Claude:
field_node enforces maxField_=22mT / maxChange_=15mT as hardcoded C++ literals (not even parameters — can't tune without recompiling), while psu_node independently enforces 80%-of-rated V/A limits from its own ROS parameters. Neither layer knows the other's limit exists. That's the architectural weak point for what's supposed to be the safety-critical part of the system.
